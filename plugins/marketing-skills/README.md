# marketing-skills

One marketing library for every project and every audience language: conversion (CRO),
copywriting, SEO and AI search, paid ads and creative, analytics and attribution, email, social,
events and video, launch, pricing, positioning, sales and growth.

It merges two open-source libraries into one set of skills, keeping the stronger version of each
topic and folding in what the other one adds:

- **[coreyhaines31/marketingskills](https://github.com/coreyhaines31/marketingskills)** by Corey
  Haines — the base for every shared topic.
- **[alirezarezvani/claude-skills](https://github.com/alirezarezvani/claude-skills)**
  (`marketing-skill/`) by Alireza Rezvani — merged into the shared topics, plus the skills only it
  has.

See [Credits](#credits). The full topic-by-topic comparison is in
[docs/COMPARISON.md](docs/COMPARISON.md); provenance and how to sync with upstream are in
[UPSTREAM.md](UPSTREAM.md).

## Install

The plugin ships in this workspace's local marketplace (`.claude-plugin/marketplace.json` at the
workspace root, marketplace name `punokawan`).

In an interactive Claude Code session:

```
/plugin marketplace add <path-to-the-workspace>
/plugin install marketing-skills@punokawan
```

Or in `~/.claude/settings.json` (user level, so every project gets it). `path` is the absolute path
of the marketplace root, the folder that contains `.claude-plugin/marketplace.json`:

```json
{
  "extraKnownMarketplaces": {
    "punokawan": { "source": { "source": "directory", "path": "/absolute/path/to/the-workspace" } }
  },
  "enabledPlugins": { "marketing-skills@punokawan": true }
}
```

Turn off any other plugin that is also named `marketing-skills` (for example
`marketing-skills@claude-code-skills`), so the two do not compete. Codex reads the same skills
through `.codex-plugin/plugin.json`.

## How the skills work together

1. **`product-marketing` first.** It writes the product's marketing context (positioning, audience,
   voice, languages and markets). Every other skill reads that context before it asks questions.
   In a workspace with several products, each product keeps its own context file
   (`projects/<project>/product-marketing.md`); a single-product repo keeps it at
   `.agents/product-marketing.md`. One product never reads another product's context.
2. **`marketing-ops` routes.** When a request spans several skills, or it is unclear which one
   fits, it picks the skills and their order.
3. **Language follows the product.** No skill assumes a language, currency or market; the context
   file says which audience languages and markets apply. Examples inside the skills are in English.

## Tools and scripts

- `tools/` — command-line clients and setup guides for about 70 marketing services (analytics, ads,
  email, CRM, SEO data). Each one reads its API key from an environment variable and sends data
  only to that service. They do nothing without a key. Connecting an account is the owner's call.
- `skills/<name>/scripts/` — small calculators, scorers and validators (Python standard library or
  Node, no installs). They work on the numbers or files you pass in. A script fetches a web page
  only when you give it a URL.
- Maintenance runs from the workspace root with `bash .claude/scripts/skills.sh` (see the workspace
  `CONTRIBUTING.md`): `validate marketing-skills` checks frontmatter, names, links and scripts;
  `index marketing-skills` rebuilds the skill table above; `sources check marketing-skills` checks
  every skill's `SOURCES.md` (a row for each section and file, `as is` rows that match upstream);
  `overlap <skill>` finds name and topic clashes before a skill is added.

upstream (`bash .claude/scripts/skills.sh sources check marketing-skills` from the workspace root). When two sources cover the same
