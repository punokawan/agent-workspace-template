# Storage Management

The workspace holds every project's checkouts on one small disk. Naive `git worktree` usage
fills it on the second feature. Every worktree shares build artifacts with a central cache
instead of owning its own. Run `storage.sh report` for current numbers — never quote old ones.

## Budget model

| Layer | Location | Size | Shared? |
|---|---|---|---|
| Source checkout | `projects/<project>/<repo>/` | 5–200 MB each | no |
| Worktree source | `.wt/<project>/<repo>/<slug>/` | source size only | no |
| Build cache | `.cache/<project>/<repo>/<name>/` | several GB | **yes — one copy for all worktrees** |
| Run state | `.claude/agentic-state/<run-id>/` | KB | n/a |

A worktree costs its source size, not GBs, because each stack's `shared_artifacts`
(`templates/stacks/<stack>.json` — e.g. Flutter `build`, Node `node_modules`) are symlinked
into `.cache/`.

`.dart_tool` is per worktree (~270 MB): parallel `flutter test`/`analyze` runs in two worktrees
overwrote each other's package config when it was shared (2026-10-15).

## Hard rules

1. **Never create a worktree with `git worktree add` directly.** Use `/wt-start`, which links
   caches immediately. A raw `git worktree add` followed by a build costs GBs.
2. **Cap: 10 concurrent worktrees across the workspace.** The next one triggers LRU pruning of
   the least-recently-touched clean one. Override with `STUDIO_WT_CAP` only if you have measured
   free space.
3. **Pre-flight before any worktree or full build:** run `storage.sh report`. If the verdict is
   `CRITICAL` (<15 GB free), prune before proceeding. Do not start work on a CRITICAL disk.
4. **Shared caches are not concurrency-safe.** Two worktrees must not run `flutter build`,
   `pub get`, `next build`, or `npm install` at the same time — they write the same cache.
   Sequence full builds; `analyze` / `lint` / `tsc` / `go vet` / unit tests are safe in parallel.
5. **Never prune `.git`, source files, `.cache` while a build is running, or `.claude/agentic-state/`.**

## Commands

```bash
.claude/scripts/storage.sh report            # where the bytes are + verdict
.claude/scripts/storage.sh prune             # dry run — lists what would go
.claude/scripts/storage.sh prune --force     # actually reclaim
.claude/scripts/storage.sh link <project> <repo> <slug> # (re)link a worktree to shared cache
.claude/scripts/storage.sh doctor            # assert no worktree holds real artifacts
```

Slash commands: `/disk-report`, `/disk-prune`.

## Safe-to-delete inventory

Each stack declares its regenerable dirs as `prune_dirs` in `templates/stacks/<stack>.json`;
`storage.sh prune` deletes only those. Deleting them loses no work.

| Path (under `projects/<project>/<repo>/`) | Regenerated by |
|---|---|
| Flutter `build/`, `.dart_tool/`, `coverage/` | `fvm flutter build` / `pub get` / `test --coverage` |
| Flutter `ios/Pods/` | `pod install` |
| Next.js `.next/`, `.turbo/`, `coverage/` | `npm run build` |
| `**/.DS_Store` | Finder |

**Never auto-delete:** `.env*`, `google-services.json`, `GoogleService-Info.plist`,
`*.jks` / keystores, `node_modules/` in a checkout (a running dev server needs it; worktrees link it from the shared cache),
native libs a repo keeps untracked (e.g. ObjectBox `download/*.dylib` in example/app — needed for
`flutter test` and *not* trivially regenerated), any untracked source.

## Reporting rule

State reclaimed space as a **measured delta** from `free_bytes` before/after — never estimate.
If you did not run the script, say `unverified` rather than quoting a number.
